# JODO resident release checklist

The first milestone is a hosted web pilot with one society, a committee member, guards and a few residents. Complete the first section before introducing real resident data. The later sections cover wider rollout and optional integrations.

## Before a pilot with real residents

- [ ] Separate the private demo from the resident deployment. Set the resident Vercel domain and Supabase settings, verify restricted previews, initialize the production schema and confirm no demo users or data are present. Record the release commit and the rollback deployment. The current demo URL still redirects to Vercel sign-in. [Deployment setup](../README.md#resident-release)
- [ ] Enable production SMS and CAPTCHA together. Hosted sign-in now requires the Turnstile site key. Verify the matching provider configuration, real carrier delivery, resend, expiration, incorrect codes, throttling, provider failure and sign-out. Set and test SMS abuse and spending limits. [Sign-in configuration](../lib/phone-auth.ts#L11) · [Supabase phone sign-in](https://supabase.com/docs/guides/auth/phone-login)
- [x] Protect private receipts after flat turnover. The flat retains its bill history and balance. Residents can read a private receipt only when the committee identifies them as the payer at entry and their original verified residency is still active. Legacy and unshared private receipts are committee-only. [Bill and receipt rules](../lib/society-finance.ts#L164)
- [x] Scope the inbox to active residency. Old notices, gate updates and other society alerts stay private after departure and rejoining. Legacy live notifications without a residency reference are hidden. [Inbox query](../lib/notify.ts#L15)
- [x] Close stale gate entries and allow cancellation. Ordinary requests give the resident 30 minutes to respond. An ordinary approval gives a separate 30 minutes to check in. Guards can cancel unused tickets, and residents can revoke unused guest passes. Guest passes still use their original 24-hour deadline, and visitors already inside can still check out. [Gate state rules](../lib/society-gate.ts#L77) · [Gate desk](../app/society/visitors/page.tsx#L129)
- [ ] Rehearse a guard call or intercom process for residents with JODO closed, denied entry, no response and an internet outage. The current alert is delivered to the in-app inbox and the page refreshes in the foreground. [Gate notifications](../lib/society-gate.ts#L143) · [Foreground refresh](../components/AutoRefresh.tsx#L15)
- [x] Allow safe enrollment for a guard who signed in first. The committee can enroll an unassigned account with no resident history. Enrollment ends the early sign-in session, and the guard signs in again to reach the desk. [Guard enrollment](../lib/society-access.ts#L41)
- [ ] Establish account and staff recovery. Cover lost or changed numbers, sessions on old devices, cross-society guard reassignment and secretary handover. Confirm identity before changing roles, moving assignments or revoking sessions. [Initial secretary setup](../scripts/init-postgres.ts#L69)
- [ ] Choose how pilot dues are reconciled. Today JODO bills verified flats only and records one full payment per bill. For real balances, keep a reconciliation ledger and a documented correction process. Verify vacant and unregistered flats, duplicate references, incorrect bills and expense corrections before using JODO as the system of record. [Monthly dues](../lib/society-finance.ts#L89) · [Payment recording](../lib/society-finance.ts#L178)
- [ ] Assign an operator for support, setup enquiries and incidents. Set a monitored help address, agree on response times, review the draft privacy policy and terms, and define how to handle access, corrections and retention for resident and visitor records. [Help](../app/help/page.tsx#L130) · [Privacy draft](../app/privacy/page.tsx) · [Terms draft](../app/terms/page.tsx)
- [ ] Verify a real backup, restore and rollback on staging. Start with a representative database, run the schema upgrade, restore the backup into an isolated environment and confirm roles, balances and attachments. Add release checks for migrations before deploying future changes. Enable error and uptime alerts with a response owner. [Database initializer](../scripts/init-postgres.ts#L94) · [Supabase backups](https://supabase.com/docs/guides/platform/backups) · [Vercel launch checklist](https://vercel.com/docs/production-checklist)
- [ ] Run the hosted role matrix using real devices and an isolated staging database. Include resident sign-in and approval, decline and retry, lost access after revocation, gate entry and checkout, guest passes, notices, meetings, polls, amenities, complaints, dues, receipts and the ops enquiry queue. Include two societies to check access boundaries and repeat submissions to check consistency. [Local test configuration](../vitest.config.mts)

## Before wider use

- [ ] Add opt-in push notifications for visitor approvals if residents are expected to respond while JODO is closed. Test permissions, expired subscriptions, delivery retries, device lock screens and the guard fallback on actual phones. [Browser Push API](https://developer.mozilla.org/en-US/docs/Web/API/Push_API)
- [ ] Close the rest of the workflow loops. Add an update when membership requests are submitted and decided, a way to amend or cancel a pending request, notice corrections, meeting reschedule or cancellation, committee-managed amenity closures, and complaint follow-up after resolution. Prioritize using results from the pilot. [Membership review](../lib/society-membership.ts#L28) · [Community actions](../app/society/community/actions.ts#L34) · [Complaint transitions](../lib/society-complaints.ts#L105)
- [ ] Add the flat roster and auditable finance corrections if the committee will use JODO as its main ledger. Agree on partial payments, reversals, adjustments, settlements and exports with the committee. Test the statement totals after each correction.
- [ ] Test load and accessibility on a representative society. Measure gate-refresh and alert latency, concurrent writes and pool contention on hosted PostgreSQL. Add search and pagination where needed in long logs and directories. Check low bandwidth, keyboard and screen-reader use, and English and Hindi on representative phones. [Database connections and transaction lock](../lib/db.ts#L246) · [Document language](../app/layout.tsx#L38)
- [x] Align the landing page and enquiry confirmations with available features. Booking approvals appear only on the demo site, and enquiry confirmations document receipt without promising a callback time. [Product copy](../components/Landing.tsx#L226) · [Enquiry responses](../app/actions.ts#L419)
- [ ] Make automated release checks repeatable. Run tests, typecheck and build in CI. Add a PostgreSQL test job and keep the browser smoke and its fixtures versioned for hosted sign-off.

## Separate release tracks

- [ ] Android distribution. The current APK opens the private demo in a browser. For a resident release, configure the resident URL, choose the production application ID and maintain a signing key. Test fresh install and upgrade on physical phones. Prepare a signed Android App Bundle if distributing through Google Play. [Demo launcher](../android/README.md) · [Android app signing](https://developer.android.com/studio/publish/app-signing)
- [ ] Online payments and group services. Resident mode already disables simulated group bookings. Open a separate release for real payment processing, refunds, disputes, reconciliation and partner operations if these are needed. [Booking access rules](../lib/authz.ts#L49)

## Local verification

- All 175 tests passed, the production build completed, and the dependency audit reported zero vulnerabilities. Regression checks cover flat turnover, inbox access, gate expiry and cancellation, and enrolling an existing unassigned account as a guard.
- Browser checks against the local production build covered test SMS sign-in, real form submissions for resident approval and guard cancellation, guest-pass revocation, and the guard desk after enrollment and re-sign-in.
- The hosted schema initializer was exercised against empty and older PostgreSQL-compatible schemas with synthetic data. Run it against the chosen pilot schema before deploying the app so the new inbox, gate and receipt fields are available.
- Production carrier delivery, managed PostgreSQL behavior, backup restoration and the resident deployment still need hosted verification.
